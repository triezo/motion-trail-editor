# Motion Trail Editor (+ свой «AnimEasy на минималках»)

Аддон для Blender 4.3+ (проверен на 4.3.2 и 5.2.2): траектория движения объекта или кости прямо во вьюпорте, которую можно
редактировать — двигать ключи мышкой, вращать и масштабировать группы ключей, вставлять и удалять ключи.
Плюс инструменты аниматора в шапке Dope Sheet / Timeline: сохранённые выделения, Tween, Euler Filter,
AnimOffset, Ghosts, Silhouette (см. «Кнопки в шапке»).

## Возможности

- Траектория объектов и pose-костей с учётом родителей, констрейнтов и IK (считается движком
  motion paths самого Blender, поэтому совпадает с реальным движением).
- Затухание до/после текущего кадра, точки на каждом кадре (видно spacing), кружок на текущем кадре.
- Ключи — круглые точки на траектории. Клик/перетаскивание, box select, G / R / S.
- Правка точки меняет ключи `location` (с учётом родителя на этом кадре — точка встаёт ровно туда,
  куда её перетащили). Если на этом кадре нет ключа location — он создаётся.
- Хвостики (тангенсы) у выделенных ключей — Bezier-ручки ключей `location`, показанные в 3D.
  Тянуть конец хвостика (или G) — меняет направление и скорость движения через ключ, второй хвостик
  остаётся на одной линии (кривая гладкая). S — длина хвостика (насколько кривая «держит» направление),
  R — поворот. Если выделены оба хвостика ключа, они двигаются независимо (излом).
- Alt+ПКМ по линии — вставить ключ (форма движения не меняется), Alt+ПКМ по ключу — удалить.
- Новый ключ сразу выделяется, если вставлен вручную: Alt+ПКМ на траектории, I / Insert Keyframe.
  Ключи от Auto Keying не выделяются (настройка Select New Keys: Off / Inserted by Hand / All New Keys).
- Выделение ключей синхронизируется с Graph Editor / Dope Sheet, клик выделяет и кость.
  Клик в пустоту снимает всё; сняли выделение с кости (другим инструментом, Alt+A) — её ключи тоже снимаются.
- Всё отменяется через Ctrl+Z. Список траекторий сохраняется в .blend.
- Траектория прячется вместе с оверлеями: выключены все оверлеи или галочка Motion Paths в меню оверлеев
  (для каждого вьюпорта отдельно). Скрытую траекторию нельзя кликнуть и сдвинуть.

## Установка

Аддон ставится как extension из zip (на этой машине он лежит в
`%APPDATA%\Blender Foundation\Blender\5.2\extensions\user_default\motion_trail_editor`).
Обновление: собрать zip и поставить его поверх (Install from Disk) — Blender перезагрузит аддон;
в других уже открытых окнах Blender новая версия появится после их перезапуска.

Пакеты собирает `python dev/package.py` → папка `dist/`:

- `motion_trail_editor-<версия>.zip` — extension (Blender 4.2+): перетащить zip в окно Blender
  или Preferences → Get Extensions → ▾ → Install from Disk.
- `motion_trail_editor-<версия>-legacy.zip` — классический аддон: Preferences → Add-ons → ▾ → Install from Disk.

Ставить нужен один из двух. На машине, где аддон подключён ссылкой для разработки, zip не ставить —
будет две копии одного аддона.

## Как пользоваться

1. Pose Mode: выделить кости (например IK-контролы рук/ног) — или Object Mode: объекты.
2. **Alt+M** — включить/выключить траекторию для выделенного. Включается инструмент **Motion Trail**
   в тулбаре (его клавиши работают только пока он активен).
3. С инструментом Motion Trail:

| Действие | Клавиши |
|---|---|
| Выделить ключ / добавить к выделению | ЛКМ / Shift+ЛКМ |
| Перетащить ключ | ЛКМ + тянуть |
| Box select | B или тянуть ЛКМ по пустому месту (Shift — добавить, Ctrl — убрать) |
| Двигать / вращать / масштабировать выделенные ключи | G / R / S, во время — X/Y/Z ось, Shift точнее, R R — трекбол |
| Хвостик: выделить / тянуть | ЛКМ по концу хвостика / тянуть |
| Хвостик: двигать / повернуть / длина | G / R / S |
| Вставить ключ / удалить ключ под мышкой | Alt+ПКМ по линии / по ключу |
| Удалить выделенные ключи | X или Delete |
| Снять выделение (и с костей) | клик по пустому месту или Alt+A |

Клик мимо траектории работает как обычно (выделяет кости/объекты).

R / S по нескольким ключам поворачивают/масштабируют траекторию целиком вместе с хвостиками (форма
сохраняется; ручки этих ключей становятся Aligned). Центр — Pivot Point Blender: Median, Bounding Box,
3D Cursor; с Individual Origins R/S поворачивают/масштабируют хвостики каждого ключа. Если выделен один ключ,
R и S уходят Blender — поворачивается/масштабируется сам объект или кость.

Настройки — N-панель → вкладка **Motion Trail**: диапазон (сцена / превью / свой), сколько кадров
показывать до/после, цвета, размеры, поверх геометрии, Head/Tail для костей.

## Кнопки в шапке Dope Sheet / Timeline

Справа в шапке таймлайна / Dope Sheet (если не влезает — Ctrl+колесо по шапке прокручивает её). Какие группы
показывать и показывать ли их ещё и в Graph Editor — Preferences → Add-ons → Motion Trail Editor.
Все инструменты работают с выделенными костями (Pose Mode) или объектами (Object Mode).

| Кнопка | Что делает |
|---|---|
| пунктирная траектория | то же, что Alt+M — траектория выделенного (кнопка нажата, если у выделенного она включена) |
| кости ▾ (Saved Selections) | Selection Manager: **New Selection** сохраняет выделенные кости/объекты как кнопку; ▲▼ порядок, ✎ имя, цвет, ✕ удалить. Кнопки выделений появляются в шапке 3D-вьюпорта (рядом с Pose Options): клик — выделить ровно их, Shift — добавить, Ctrl — убрать. Хранятся в .blend |
| значок режима + ▾ | ▾ — режим: Tween (между соседними ключами) / Blend to Neighbor (к левому или правому ключу) / Push-Pull (преувеличить или сгладить). Сам значок — Tween перетаскиванием: клик, тянуть влево/вправо (Ctrl — шагами), клик или Enter — применить, ПКМ или Esc — отмена |
| ◆ · • · ○ · • · ◆ | быстрые значения: левый ◆ — предыдущий ключ, ○ — середина, правый ◆ — следующий ключ, • — четверти. Ставит ключ на текущем кадре (тип ключа — как в настройке Keyframe Type) |
| гироскоп | Euler Filter: убирает скачки на 360° и gimbal-флипы в ключах rotation_euler (сам поворот не меняется) |
| сдвинутые ключи + ▾ (AnimOffset) | пока включён (кнопка нажата, во вьюпорте надпись), сдвиг позы на текущем кадре переносится на **все** ключи этих каналов — или только на кадры маски (▾ → Mask, Start/End, «Mask From Range»). Auto Keying на это время выключается и потом возвращается |
| два кружка (Onion Skin) | автоматический onion: персонаж на предыдущих / следующих ключах (или каждые N кадров) полупрозрачными силуэтами — до текущего кадра одним цветом, после другим, дальние бледнее. Идёт за плейхедом (пересчёт, когда плейхед остановился; кадры кэшируются до изменения ключей). Персонаж — риг в Pose Mode или выделенные меши (сменить: ▾ → Use Selection). ▾: Keys / Frames, Before / After, Step, Flat Silhouettes, Behind Character (силуэты не рисуются поверх текущей позы). Во время проигрывания скрыт. Незакиченные правки позы при пересчёте не теряются |
| призраки | призрак — полупрозрачный снимок персонажа (меши рига в Pose Mode или выделенные меши) на текущем кадре; зачёркнутый призрак — убрать призраков этого кадра; корзина — всех; ▾ — цвета до/после, поверх всего, прятать на своём кадре. Призраки живут до закрытия файла |
| залитая фигурка | Silhouette: персонаж становится плоским чёрным во всех 3D-вьюпортах (Solid, Flat, цвет объекта); ещё раз — всё возвращается (в том числе после сохранения и открытия файла) |

## Совместимость

- Blender 4.3: классические action (`action.fcurves`), выделение костей через `Bone.select`.
- Blender 4.4+: action со слотами — правится активный слот объекта.
- Blender 5.0+: выделение костей через `PoseBone.select`.
- В 4.3 точки кадров на линии квадратные (нет встроенного шейдера круглых точек), остальное одинаково.
- Тесты (`dev/test_core.py`, `dev/test_gui.py`) запускаются в любой из версий.

## Ограничения

- Работает с активным action (как и большинство подобных аддонов). NLA-стрипы надо запечь.
- Правится `location`. Траекторию FK-кости, которую двигает вращение родителя, видно, но двигать её
  точки нечем (у таких костей location обычно заблокирован).
- Траектории костей считаются в Pose Mode. Вне Pose Mode траектория кости замораживается (рисуется бледнее)
  и пересчитывается при возврате в Pose Mode — покадровый перебор всей сцены в тяжёлых сценах занимал бы секунды.
- Пока идёт G/R/S, перетаскивание гизмо или воспроизведение, аддон ничего тяжёлого не пересчитывает — ждёт конца.
- Хвостики показываются в пространстве родителя: если родитель сам быстро движется, хвостик не будет
  точно касательным к траектории (направление собственного движения кости всё равно верное).
- Хвостики считаются для выделенных ключей (до 24 одновременно) — на каждый ключ нужен один пересчёт кадра.

## Разработка

- `dev/test_core.py` — тесты логики: `blender -b --factory-startup --python dev/test_core.py`
- `dev/test_gui.py` — интерактивный тест с симуляцией мыши/клавиатуры и скриншотами в `dev/out/`:
  `blender --factory-startup --enable-event-simulate -p 40 40 1500 950 --python dev/test_gui.py`
- `dev/test_tools_gui.py` — GUI-тест кнопок из шапки (Tween перетаскиванием, AnimOffset с настоящим G, Ghosts,
  Silhouette): `blender --factory-startup --enable-event-simulate -p 0 0 1500 900 --python dev/test_tools_gui.py -- <путь/префикс>`
- `dev/testrig.py` — тестовая сцена (риг с IK и вращающимся root, анимированный куб).
- `dev/profile_scene.py`, `dev/profile_gui.py`, `dev/make_heavy.py` — замеры скорости на копии сцены.

Производительность: во время перетаскивания ключа/хвостика сцена не пересчитывается — линия
двигается по формуле «старая позиция + J · изменение кривых location» на участке ±2 ключа, а если у кривых
сглаживание Continuous Acceleration (по умолчанию в Blender 5) — по всей кривой: там сдвиг одного ключа
меняет Auto-ручки всех ключей.
Точный пересчёт (движок motion paths Blender) делается при отпускании и только для этого участка.
Правки в Graph Editor пересчитываются, когда изменения затихли (раз в 0.2–0.4 с во время долгого драга).

Каждая траектория пересчитывается только от того, что её реально двигает: своя кость, её родители,
цели её констрейнтов (IK, Child Of, Armature — в т.ч. переключатели родителя Rigify), сам объект рига
и его родители. Ключи других костей и других ригов, Ctrl+Z чужих правок — траекторию не трогают.
Считаются только кадры вокруг плейхеда (Before/After + запас); при уходе плейхеда дальше — досчитываются.
Before/After = 0 — считается весь диапазон, как раньше.
